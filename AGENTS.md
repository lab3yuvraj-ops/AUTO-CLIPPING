# Local Codex Reel workflow

The user removed the dashboard architecture. Work here in Codex using `reel.py` and `reel_engine/`. Do not rebuild a dashboard, web server, SQL database, scheduler or hosted worker. Do not use OpenAI, Groq, AssemblyAI or hosted Hugging Face inference. Cached Whisper/pyannote models transcribe locally; Codex handles editorial judgment interactively.

For “onboarding”, follow `ONBOARDING.md`. Ask for the student's own YouTube channel URL/ID. Have them enter their own ZERNIO_API_KEY and ZERNIO_INSTAGRAM_ID in the local private `.env` editor, or use the hidden terminal prompt; never ask for passwords, print credentials, or put API keys in command arguments, Git, public files or ordinary chat. Explain that the Instagram ID must be the connected account ID in Zernio. Run `reel.py onboarding --channel CHANNEL --from-env` to verify access and save their local connection. Only when local speaker models need initial provisioning, guide them through accepting the gated model terms and setting HF_TOKEN privately, then `reel.py prepare-models --download`. Public YouTube lookup needs no API key; ask for an authorized local cookie-file path only if downloading is challenged. Never copy the original creator's connection, secrets, cookies, videos or processing/publication history into a student checkout. Each student uses a separate local clone. Onboarding does not publish a test post.

“YouTube analyze”, “analyze YouTube” and “analyze video” are equivalent trigger phrases. If the channel is not configured, do onboarding first. Otherwise use that checkout's saved channel. After editing, show the real clip and ask “Do you want to upload this video to Instagram?” Publish only after clear human approval of that exact preview, and reconcile the saved publication until the post ID/link is confirmed. A clean clone does not include historical reference videos; the output rules below are the portable reference.

For “analyze video” or “analyze YouTube”, first ask: “How many short videos would you like from this source—one, two, or another number?” If the current request already specifies a number, use it without asking again. Wait for this answer before selection/rendering. “Analyze video” uses the supplied file/URL; if no source is supplied, use the connected YouTube channel's latest released upload. Run `.venv/Scripts/python.exe reel.py analyze --clips NUMBER` (with `--url URL` or `--file PATH` when supplied). Reuse saved sources and transcripts.

Inspect the entire transcript and actual chronological source frames, not just the beginning or the first plausible passage. Recheck missed speech locally. Rank complete, independently understandable 30–60-second moments by opening, context, story/exchange/reveal, intact payoff and natural ending; duration alone is not evidence of an engaging clip. Avoid substantially overlapping or repetitive selections. Treat the requested count as a target, never a quota: if only one moment is strong, say so plainly even for a ten-minute source. Do not pad, fabricate, promise virality, or silently render a weak second clip.

Save `selection-report.json` with the requested count, recommended count, source coverage, candidate timestamps, evidence, strengths, weaknesses and reasons for rejection. Tell the user which candidates are strong and which are weaker. If a complete second candidate is weaker, explain why and ask whether they still want it before rendering that weaker candidate; proceed with authorized strong clips independently. If no additional complete 30–60-second moment exists, report that instead of offering an impossible clip. Never override duration, complete-sentence, crop or caption requirements to meet the requested count.

For each selected clip, align Roman captions and write a separate edit JSON. Use separate clip job/output paths when producing multiple clips so one render or approval cannot overwrite another; share the saved source/transcript and keep the source job ID in each clip record. Run `reel.py render JOB_ID --edit EDIT.json`; return the real MP4(s) and ask for approval of the exact previews. Report actual blockers instead of simulating success.

Before a full render, run `reel.py review JOB_ID --edit EDIT.json` and inspect the saved combined source/crop/caption review pages, especially moving characters and scene transitions. Batch uncertain speech with `reel.py recheck JOB_ID --range START:END --range START:END`; one Whisper load serves all passages and results never silently replace the full transcript. Preserve the Whisper small model, beam size 5, final 1080x1920/30fps, caption treatment and 1.2-second easing. Default encoding remains libx264 CRF18; GPU encoding is experimental until compared against the reference. Reuse only hash-verified lossless edits. Do not claim a 5–6-minute end-to-end result from a render-only benchmark.

For “good to go”, identify the exact preview approved by the human; clarify if ambiguous. Run `reel.py publish JOB_ID --confirmed`. Poll the same job until Instagram confirms its post ID/link. Never publish from hypothetical examples or general setup instructions. Do not discard a pending provider request or create another post to bypass uncertainty. The approved reference is migrated as job `web3approved`.

Approved reference: `optional local approved reference (not distributed)`; recipe: `workflow/approved-reference.json`.

- One contiguous full-screen 1080 × 1920 source crop; no inset, duplicated scene, blurred border or fitted landscape.
- Complete 30–60-second story with engaging opening and intact payoff; no padding or cut-off words/sentences.
- Append the supplied CTA from `assets/cta/watch-full-video.mp4`, trimmed to exactly 4 seconds, to each new Reel; defaults live in `workflow/output-defaults.json`. The 30–60-second limit applies to the story, with the CTA appended afterward. Preserve the original laughter/reaction and its audio once at their original speed, then go directly into the CTA when the source ending finishes. Never loop laughter, repeat background sound, add a freeze-frame hold, or stretch the ending. This correction supersedes the previous two-second hold. Preserve story encoding by concatenating compatible H.264/AAC parts without recompressing it.
- Track the visible speaker or the person/object/text/action the narration refers to. Audio IDs do not identify left/right characters. Inspect chronological identity anchors in difficult or multi-character scenes. Hold a stable crop when uncertain; never transplant reference boxes to new footage.
- Always crop the entire source height: top at 0, bottom at source height, width = source height × 9/16. Move horizontally only with 1.2-second easing; reset at actual scene cuts. Do not add zoom or vertical movement based on character/object box size. Preserve natural camera movement already in the source. This explicit correction supersedes the older reference's extra zoom.
- Roman Hindi/Hinglish preserves wording, names and original English. Caption highlighting uses the final source-to-edit timing map.
- Creepster captions, black outline/shadow, white default and only the spoken word red. Usually two words per phrase. Lock all captions at (500,1420) unless the user explicitly changes this.
- Save sources, full transcripts, selection evidence, cuts, alignment, character anchors, render checks and publication state. Do not claim human listening or perfect automatic identity without evidence. Ask for approval before publication.

Preserve source media, approved videos, cached local models and current YouTube/Zernio credentials. Dashboard deletion does not authorize deleting those assets.
